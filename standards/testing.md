# 测试与验证规范

> 本文只提供业务仓库未明确规定时的缺省规则。测试框架、目录、命名、构建命令和覆盖要求优先遵守目标仓库或模块的 `AGENTS.md`。

## 1. 测试从验收标准出发

每个核心验收标准至少映射到一条测试或人工验证。测试计划同时覆盖：

- 正常路径与主要业务分支。
- 空值、边界值、重复请求和非法状态转换。
- 依赖超时、失败、降级与重试边界。
- 并发、幂等和事务一致性（适用时）。
- 旧数据、旧接口和开关关闭路径的兼容回归。

## 2. 单元测试

- 测行为和契约，不绑定无意义的内部调用顺序。
- 测试名清楚表达前置条件、动作和结果。
- mock 只隔离外部边界，不把被测核心逻辑本身 mock 掉。
- 修复缺陷时先补能复现缺陷的测试，或说明无法自动化的原因。

## 3. 结果证据

`verification.md` 对每项验证记录：命令、执行目录、环境、结果、日期和未覆盖范围。

只能使用以下表述：

- `passed`：本轮实际运行且成功。
- `failed`：本轮实际运行但失败，保留关键错误与影响。
- `not_run`：未运行并说明原因。
- `blocked`：因明确外部条件无法运行。

编译成功不等于单测通过，单测通过不等于集成链路通过。
