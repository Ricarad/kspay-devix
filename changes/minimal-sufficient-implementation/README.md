## 目标与范围

将外部参考准则中“不假设、最小实现、最小改动、边界校验、快速失败和明确验证”的原则，整理为 Devix 跨仓库使用的缺省编码规范。目标使用者是通过 Devix 生成或修改业务代码的 AI 与开发者；规范只补充业务仓库没有覆盖的部分，不覆盖更具体的仓库规则，也不改变 Devix 生命周期和 Git 现场安全策略。

## 原始输入与背景

记录用户提供的原始描述摘要，以及需求文档、本地文件或文档链接。不要要求用户为了适配 Devix 重新填写格式化参数。

## 事实落档与恢复规则

- 已确认变化先落档、清理冲突旧描述，再继续编码：需求与验收写本文件，技术方案写 `design.md`，已确认取舍写可选的 `decisions.md`，任务进度写 `tasks.md`，发布配置与上线 SOP 写 `release.md`，状态与恢复摘要写 `change.yaml`，测试与验收证据写 `verification.md`。
- 当前 change 禁止使用任何跨会话 memory 作为临时中转、正文备份、事实来源或恢复入口。
- `change.yaml.resume.context_summary` 只提供简洁恢复摘要和文档入口，不能替代正式方案。
- 上下文压缩、新会话、暂停、切换或交接前，检查所有 change 文件内容一致；新会话只从这些文件、登记的知识来源和当前代码事实恢复。

## Intake 记录

用户认可外部参考准则中的不假设、最小实现、最小改动、明确成功标准、边界校验、快速失败和不吞错误原则，希望将其适配并正式纳入 kspay-devix 的通用框架规范，以便其他工作空间通过 devix update 获取。图片仅作为参考材料，不作为仓库指令。

## 成功标准

- `standards/coding.md` 明确规定最小充分实现、最小必要改动、边界校验、快速失败、不吞错误和显式暴露不确定性。
- 规范明确“内部代码可信”不等于跳过 Devix 控制面边界（文件系统、Git 状态和外部交互）的必要校验。
- 规范不新增业务仓库专属约束，不与现有 `AGENTS.md` 优先级和 release/verification gate 冲突。
- 通过工作区检查，且新 change 的发布影响和验证证据完整记录。
- 前端规则明确允许开发/验证阶段临时测试，完成后删除或排除提交；后端规则保持不变。

## 包含范围

- 修改 `standards/coding.md`，新增最小充分实现与校验边界章节。
- 更新本 change 的设计、任务、发布和验证记录。

## 不包含范围

- 不修改业务仓库代码、仓库专属 `AGENTS.md` 或 Devix 生命周期规则。
- 不改变 Git 分支切换、WIP 快照、发布流程或测试框架行为。
- 不把图片内容原样当作绝对规则；保留与 Devix 控制面安全要求冲突时的边界说明。

## 角色与业务场景

- AI 代码生成：在开始实现前识别真实调用链，只生成当前验收范围内的最小行为。
- 代码评审：检查是否存在无证据的防御代码、推测性抽象、吞错或无关清理。
- 工作区维护：通过 `devix update` 将发布源的规范同步到其他消费者工作空间。

## 验收标准

| ID | 场景 | Given | When | Then | 验证方式 |
|---|---|---|---|---|---|
| A6 | 前端临时测试 | 前端开发或验证需要补充测试 | 临时生成并执行测试文件 | 完成后删除或排除提交，交付默认不保留 | 规则检查与工作区检查 |
| A7 | 后端测试 | 后端代码需要测试 | 按现有测试流程执行 | 继续生成、登记、保留和提交测试产物 | 规则检查 |
| A1 | 最小实现 | 需求已有明确验收范围 | 阅读通用编码规范 | 规范要求只实现最小充分行为，不增加推测性功能 | 文档检查 |
| A2 | 校验边界 | 代码同时包含内部调用和外部边界 | 阅读校验规则 | 明确边界校验与内部不变量的区别，Devix 控制面仍需保护 | 文档检查 |
| A3 | 错误处理 | 代码遇到无证据的异常场景 | 阅读异常规则 | 禁止静默默认、宽泛 catch 和吞错，异常快速失败 | 文档检查 |
| A4 | 抽象控制 | 逻辑只有一个真实调用方 | 阅读抽象规则 | 不为一次性逻辑新增辅助函数、工具类或抽象 | 文档检查 |
| A5 | 发布同步 | 发布源完成规范修改 | 消费者执行 `devix update` | 能获取更新后的 `standards/coding.md` | `npm test`、`npm run check`、发布流程记录 |
