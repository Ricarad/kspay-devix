# 技术方案

## 1. 目标、范围与约束

本 change 只修改 Devix 发布源的 `standards/coding.md`。规范采用“最小充分实现 + 边界校验 + 快速失败”的组合：鼓励信任已建立的内部契约，但把用户输入、外部 API、网络、文件系统和 Git 状态视为必须保护的系统边界。它是业务仓库未明确规定时的缺省规则，不能覆盖业务仓库更具体的 `AGENTS.md`，也不能削弱 Devix 自身的 change、分支和发布 gate。

## 2. 现状与真实代码路径

- `standards/README.md` 将 `standards/coding.md` 定义为跨仓库缺省编码规范，并明确仓库 `AGENTS.md` 优先。
- 根级 `AGENTS.md` 已规定真实调用链、最小范围、错误不吞、验收与验证 gate；本次只把图片中的实现纪律补成可直接执行的编码条款。
- `devix update` 的发布同步路径会复制平台托管的 `standards/`，因此不需要新增 CLI 或消费者侧代码。
- 当前仓库不存在 `.codegraph/`，本次没有可同步的 CodeGraph 索引；以上路径通过直接读取规则文件、安装文档和测试脚本核对。

列出入口、调用链、数据流、配置、外部依赖和已验证证据。已建立 CodeGraph 索引时，记录 sync 对应的工作目录/分支，并优先使用 CodeGraph 得到源码与调用链。

## 3. 方案概览

在 `standards/coding.md` 的修改原则之后新增独立章节，集中说明：最小充分实现、只改必要范围、系统边界校验、对不变量快速失败、真实复用后再抽象，以及显式暴露不确定性并以验证结果为准。原有兼容、安全、日志和提交规则保持不变。

|---|---|---|---|

## 5. 接口、数据与状态设计

无接口、数据模型或状态机变更。规范通过现有 `devix update` 文件同步机制传播。

## 6. 异常、幂等、并发与事务

无运行时代码变更。本次规则明确：内部不变量不重复防御，但控制面边界仍必须校验；不变量破坏时快速失败且不吞错误。

## 7. 兼容、灰度与代码级回滚约束

实际发布配置、环境差异、执行顺序、监控与操作回滚写入 [`release.md`](./release.md)，本节只说明技术方案中的兼容和代码级约束。

规范是缺省行为，业务仓库已有规则继续优先。回滚只需恢复 `standards/coding.md` 的上一版本并重新发布；不涉及业务数据或运行时兼容。

## 8. 测试设计

- 文档静态检查：确认新章节包含六类核心约束，且没有与现有规则冲突的绝对化表述。
- 工作区检查：运行 `npm test` 和 `npm run check`，验证模板、YAML、Markdown 链接、包边界和现有 CLI 回归。
- 发布同步检查：确认 `devix update` 的既有同步清单包含 `standards/`，无需新增同步逻辑。

## 9. 风险、替代方案与未决项

- 风险：将“只在边界校验”误读为跳过 Devix 自身的文件系统/Git 安全检查。通过正文明确这些属于控制面边界来降低风险。
- 风险：规范过于抽象，评审时难以判断“真实证据”。通过“真实调用方、验收标准和代码事实”作为判断依据，不新增形式化工具。
- 替代方案：直接改根级 `AGENTS.md`。未采用，因为该文件负责工作流和现场安全，本次内容属于跨仓库编码缺省规范。
- 未决项：无。
